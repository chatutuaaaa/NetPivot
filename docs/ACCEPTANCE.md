# NetPivot 验收与实施记录模板

适用范围为设计 0.1 的交付验收。自动化结果见 [运行指南](RUN.md)。每次真机验收请记录版本与证据后再勾选。

## 1. 测试记录格式

每次记录：日期、构建号、客户端/扩展版本、API/网关版本、设备型号、系统版本、游戏版本、网络类型、服务器地域、成员数、主机设备、复现步骤、预期、实际、日志 request ID、结论。

统计结果附样本量和失败数；不得只保留成功样本。无法复现或没有设备时标记“未验证”，不能写“通过”。

## 2. M0：环境与构建

- [ ] Mac、Xcode、Go 与依赖提交已记录并锁定。
- [ ] 干净目录可以构建 App 和扩展，无本机私有路径依赖。
- [ ] 真机签名与 Network Extension 能力有效。
- [ ] 私钥、签名材料、数据库密码未提交仓库。
- [ ] 模拟器结果与真机结果明确区分。

## 3. M1：真实网络与游戏

- [ ] 两台不同外网设备使用虚拟 IP 双向通信。
- [ ] iPhone→iPad、iPad→iPhone 均可作为游戏主机。
- [ ] 普通移动版目标游戏实际进入农场并持续通信。
- [ ] 第三台加入后 A↔B、A↔C、B↔C 均可达。
- [ ] 网络管理员与游戏主机为不同设备仍可联机。
- [ ] 游戏测试使用可丢弃的新存档，记录实际游戏限制。
- [ ] 没有用同一物理 Wi-Fi 的自然连通冒充异地虚拟网络成功。

## 4. P0：创建与加入体验

- [ ] 首次免注册，创建不强制填名称、选节点或调整参数。
- [ ] 首次 VPN 授权说明清楚，允许/拒绝/重试均正确。
- [ ] 链接、扫码、8 位短码进入同一兑换流程。
- [ ] 链接未安装回退页能提供短码与后续操作说明。
- [ ] 邀请过期、已关闭、网络满员都有明确提示。
- [ ] 重复提交不会创建重复网络或重复成员。
- [ ] 最近网络一键重连，虚拟 IP 保持稳定。
- [ ] 能复制任一成员的 IP，不将管理员误当成游戏主机。
- [ ] 管理员可刷新邀请、移除成员、转让或解散。
- [ ] 普通成员不能执行管理员动作。

## 5. P0：多设备能力

| 场景 | 检查项目 | 结果 |
| --- | --- | --- |
| 3 台 | 3 对路径双向可达 | 未验证 |
| 4 台 | 6 对路径双向可达、并发业务正常 | 未验证 |
| 8 台 | 28 对路径双向可达、共 56 个有向测试 | 未验证 |
| 第 9 台 | 明确告知首版网络人数已满，不挤掉现有成员 | 未验证 |
| 多网络 | 两个独立网络，任意跨网络尝试被拒绝 | 未验证 |
| 管理员离线 | 网络不依赖管理员设备充当转发服务器 | 未验证 |
| 游戏主机离线 | 网络继续存在，游戏断开原因区分显示 | 未验证 |
| 一人离开 | 其余成员的地址和既有连接不无故重置 | 未验证 |

8 台组网验收使用通用测试流量；不能因为某款游戏人数上限不足 8 人，就跳过网络层多设备测试。

## 6. P0：安全与权限

- [ ] 邀请码限速、有效期和兑换次数在服务端实施。
- [ ] 并发抢最后一个名额不突破容量。
- [ ] 伪造网络 ID、成员 ID、IP 或角色均被拒绝。
- [ ] 无效设备签名、重放挑战、过期令牌无法获取配置。
- [ ] WireGuard 源地址约束与网关防火墙同时有效。
- [ ] 所有跨网络路径失败，包括已存在的 UDP 流。
- [ ] 撤销正常 10 秒内生效；控制面失联不超过有效租约。
- [ ] 网关重启不重新激活过期成员。
- [ ] 客户端拒绝默认路由、越界地址、未知配置版本和旧 revision。
- [ ] UI、日志、邀请链接分析系统不泄露私钥或完整令牌。
- [ ] 网关模式隐私说明没有误写成服务器不可解密。

## 7. P0：系统与界面

- [ ] iPhone 小屏/大屏、横竖屏均可完成创建加入。
- [ ] iPad 宽窗口为侧栏+详情，窄窗口正确折叠。
- [ ] 调整窗口不重启隧道或丢失表单。
- [ ] 深浅模式、最大字体、VoiceOver、键盘操作可用。
- [ ] 8 成员、长名称、长错误文案无裁切和重叠。
- [ ] 用户断开后不被后台重试重新连上。
- [ ] 主 App 挂起、返回前台、设备重启后的状态正确。
- [ ] 锁屏和游戏切后台导致的游戏行为与隧道状态分开记录。
- [ ] 其他 VPN 或系统配置冲突有可理解的提示。
- [ ] 普通上网和系统 DNS 行为未被意外接管。

## 8. P1：路径、稳定性与性能

- [ ] Wi-Fi↔Wi-Fi、Wi-Fi↔蜂窝、蜂窝↔蜂窝分别测试。
- [ ] IPv4、双栈、IPv6-only/NAT64 下外层连接验证。
- [ ] 限制性 NAT、UDP 封锁和同地址家庭网络场景有结果。
- [ ] 同一实际传输映射用于直连检查与 WireGuard 数据。
- [ ] 三台以上混合直连/网关路径逐对可达。
- [ ] 某一成员直连失败，不影响其他成员已有路径。
- [ ] 切换的版本确认、超时回滚、旧信令丢弃均验证。
- [ ] 1%、3%、5% 丢包及 20/50/100 ms 附加延迟下有记录。
- [ ] 网络短断、Wi-Fi/蜂窝切换、网关失效可恢复。
- [ ] 2 小时真实游戏测试完成，各主要设备组合至少 3 次。
- [ ] 8 台并发测试记录网关带宽、客户端内存和耗电。
- [ ] 创建/加入至少 100 次，报告 P50/P95 和失败率。
- [ ] 端到端 RTT 与节点 RTT 分开，不用节点延迟冒充玩家延迟。
- [ ] 路径切换没有无限重试、频繁抖动或无界队列。

性能指标按 DESIGN 的目标表核对；未达标的项说明原因、影响和下一步，不能删掉失败数据。

## 9. 运维与发行

- [ ] 数据库备份可恢复，恢复演练有记录。
- [ ] 防火墙先于网关启动，加载失败时拒绝转发。
- [ ] 主备网关配置同步成功后才开放切换。
- [ ] 控制服务、代理、数据库异常时状态和告警正确。
- [ ] 应用回滚、配置回滚与数据库兼容策略实际验证。
- [ ] 第三方许可证、隐私说明、测试说明齐全。
- [ ] TestFlight 包与验收构建号一致。
- [ ] 公开上架前重新检查 Apple 规则和目标发行地区条件。

## 10. 发布判定

**可用内测版**：M0、M1、全部 P0 通过；允许只提供网关路径，但必须准确标注。

**正式质量版**：以上加 P1 通过，并具备可执行的运维恢复方案。目标游戏、系统、网络条件有明确支持列表。

任何私钥泄漏、跨网络访问、撤销失效、地址重复、主要设备无法建立隧道、游戏核心场景失败，均为阻断发布的问题。
